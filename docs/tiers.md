# 难度分级

档位按**实测胜率**排，不按推演次数排。

## 实测口径

- 我方固定地主位（`--seat 0`），对手是两个 DouZero WP 农民（`DZ_SOTA_FARMER=1` 的第二座 bridge）
- 每档 200 副，`seed=1`，`PYTHONHASHSEED=0`
- 复现：`powershell -ExecutionPolicy Bypass -File tools\bench-ladder.ps1 -Tiers "free,go,plus,pro"`

## 现在这五档

| 档位 | 预算 | 单手上限 | 胜率 | 平均决策 |
|---|---|---|---|---|
| `free` | 0 | 0 | 0.135 | 2.52 ms |
| `go` | 0 | 0 | 0.56 | 2.52 ms |
| `plus` | 60 | 200 ms | 0.56 | 13.0 ms |
| `pro` | 250 | 600 ms | **0.60** | 42.3 ms |
| `sota` | 0（一次神经网络前向） | 4000 ms | **0.674** | 2.8 ms |

## 旧阶梯（8 档）为什么砍

| 档位 | 胜率 | 问题 |
|---|---|---|
| `free` | 0.05 | 旧逻辑 55% 纯随机 + 45% 专挑最差的一手，低到不像在打牌 |
| `go` | 0.56 | 正常 |
| `plus` | 0.50 | 12 次推演 + 固定 3% 门槛，拿噪声把启发式翻掉了 |
| `pro100` | 0.56 | 与 `go` 无差别 |
| `pro200` | 0.585 | 略好 |
| `pro500` | 0.575 | 与 `pro200` 无差别，只是更慢 |
| `pro9999` | 未跑完 | 4 秒/手，12 副要 24 分钟，无法验收 |
| `sota` | 0.674 | 正常 |

## 三处具体改法

1. **`free` 重写**：先排除炸弹/王炸，再从「张数最少的一手」里按点数升序取最小（80%），20% 在同档随机。弱，但不会拆炸、不会主动开炸。
2. **`plus` 不再翻车**：推翻启发式的门槛从固定 0.03 改成按样本量算的 Wilson 标准误，`margin = clamp(se, 0.03, 0.12)`。样本少时门槛高，宁愿照启发式打。
3. **合并档位**：`pro100/pro200/pro500/pro9999/max` 全部映射到 `pro`（250 次 / 600 ms）。别名在 `TIER_ALIAS`，老存档 `ddz-tiers` 读进来会自动迁移。

## 为什么不设 `max` 档

试过 700 次推演 / 1500 ms：200 副 0.58，比 `pro` 的 0.60 还低，耗时 100 ms 是 `pro` 的 2.4 倍。
原因是推演里对手按本引擎的简化策略走，推演越多越是对着「假对手」优化，对真 DouZero 反而不划算。
`pro` 是这条收益曲线的拐点。
